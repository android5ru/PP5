Инварианты:
1. Каждая строка полного запуска обработана ровно один раз;
Для каждого файла создаётся ровно один итератор в начале обработки, и этот итератор используется только одним потоком. В конечном отчёте, количество обработанных строк соответствует действительности.

2. Для каждого URL requests = successful + errors;
Проверка после завершения работы показывает действительность утверждения.

3. MaxDuration <= totalDuration при наличии запросов;
В UrlAccumulator.add() поле totalDurationMillis увеличивается на entry.durationMillis() для каждой записи, а maxDurationMillis обновляется как Math.max(maxDurationMillis, entry.durationMillis()).
Поскольку все значения durationMillis неотрицательны (генератор создаёт значения от 1 до 500), максимум одного элемента не может превышать сумму всех элементов.

4. 0 <= activeFiles <= semaphoreLimit;
Значение activeFiles увеличивается на 1 только после успешного вызова semaphore.acquire(), который блокирует поток, если все разрешения исчерпаны, поэтому activeFiles не может превысить semaphoreLimit.

5. После завершения анализа activeFiles равно нулю;
Это достигается путем: увеличения счетчика после получения разрешения семафора и всегда уменьшение в блоке finally, и главный поток ждёт завершение всех потоков для формирования результата

6. Один повреждённый файл не мешает обработке остальных;
Ошибка парсинга строки перехватывается внутренним блоком try-catch, который увеличивает corruptedEntries и продолжает чтение следующей строки того же файла

7. В программе нет дедлока.
Захвата ресурсов: сначала semaphore.acquire(), затем synchronized внутри GlobalAccumulator.add(), что исключает циклическое ожидание.
Поток никогда не удерживает synchronized-монитор во время ожидания semaphore.acquire(), потому что acquire() вызывается до входа в synchronized метод.
Разрешение семафора возвращается в блоке finally, который выполняется даже при исключении.
